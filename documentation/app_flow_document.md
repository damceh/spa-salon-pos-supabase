# App Flow Document

## Onboarding and Sign-In/Sign-Up
When a new staff member or administrator first arrives at the Spa Salon POS application, they land on a clean and informative login page. From there, they can choose to sign up for a new account or log in with existing credentials. The sign-up process prompts them to enter an email address, a password, and to confirm that password. Behind the scenes, Supabase Auth handles the creation of the user record and sends a verification email if email confirmation is enabled. Users may also use social login providers if configured, such as Google, by clicking the matching button and authorizing the application. Once they submit their information, they see a confirmation message and are directed to the login screen. If a user forgets their password, they click a “Forgot Password” link, enter their email address, and receive a reset link via email. That link lands them on a secure page where they provide a new password and confirm it. After resetting, they are returned to the sign-in page. Signing in is equally straightforward: a user enters their email and password and clicks the “Log In” button. Supabase verifies the credentials and returns a session token. Successful login redirects the user to the main dashboard. To sign out, the user clicks a Sign Out button in the top navigation, which clears their local session data and returns them to the login page.

## Main Dashboard or Home Page
After signing in, staff members arrive at the Main Dashboard. The page is divided into a persistent sidebar on the left and a content area on the right. The sidebar shows navigation links for the Scheduler, Point of Sale, Admin CMS, Reports, Webhook Management, and Settings. At the top of the page sits a header that displays the application name, the current user’s name, and a button for opening the command palette. The content area defaults to the Therapist Schedule Board, which visualizes today’s appointments in a calendar-like grid. At the bottom right of the dashboard, a toast notification widget appears briefly when important actions succeed or fail. From this dashboard, users click the sidebar links or use the command palette to navigate to other parts of the app, such as the POS interface or the analytics dashboard.

## Detailed Feature Flows and Page Transitions

### Therapist Schedule Board Flow
On the Therapist Schedule Board page, staff see a full-week view with time slots for each therapist. To create a new appointment, a user clicks on an empty slot or drags across time blocks. This action opens a booking modal. The modal contains a form where the staff member selects a customer (or creates a quick customer record), chooses a service, picks an available therapist, and sets the appointment duration. The form fields are validated in real time using Zod schemas so that missing or invalid entries show immediate inline feedback. Once the form is complete, the user clicks “Save.” A TanStack Query mutation sends the appointment data to Supabase, and the modal closes when the operation succeeds. Supabase’s real-time subscription pushes the update to all connected clients, and the schedule grid updates instantly without a page refresh.

### POS Interface Flow
When a receptionist or cashier navigates to the Point of Sale page, they see a split layout. On the left, a searchable list of services and products displays with thumbnails and prices. On the right, an order summary grid shows items added to the current transaction. To start a sale, the staff member clicks an item on the left, which adds it to the summary. They can adjust quantities, apply discounts, or remove items. A running total updates in real time. When ready, the user clicks “Checkout.” A payment modal appears, allowing the user to choose a payment method, enter card or cash details, and confirm the payment amount. Submitting triggers a Supabase Edge Function that processes the payment via the integrated gateway. When the payment is approved, the Edge Function writes a record to the transactions table and returns a receipt URL. The modal closes, a printable invoice opens in a new window, and the POS page resets for the next sale.

### Admin CMS Flow
Staff with manager or super admin roles access the Admin CMS section to manage core data. Upon entering this area, they see a list of entities: Therapists, Services, Products, Appointments, and Webhook Configurations. Clicking any entity opens a data table showing existing records with actions to edit, delete, or archive. To add a new record, the user clicks a “New” button which opens a form in a dialog. The form fields match the entity schema and use React Hook Form with Zod for validation. Upon submission, a mutation writes the data to Supabase and the table refreshes to show the new item. Editing or deleting follows a similar flow: a confirmation dialog appears, and after the operation completes, the table updates automatically.

### Reports and Analytics Flow
The Reports page presents interactive charts built with Recharts. At the top, users see date range selectors that filter data by day, week, or month. Selecting a range triggers a TanStack Query refetch. Once data is loaded, line charts display booking trends over time, and bar charts break down revenue by service type. Hovering over chart elements shows tooltips with exact numbers. Users may click an “Export” button to download the current data as a CSV for external analysis.

### Webhook Management Flow
Under Webhook Management, authorized users configure outgoing and incoming webhooks. The page includes a list of existing webhook endpoints with columns for events, target URLs, and status. To add a new webhook, a user clicks “Create Webhook,” fills in the event trigger and URL in a form, and submits. Supabase Edge Functions get deployed or updated automatically. Incoming webhook logs show recent events in a log table with timestamps and payload previews. If an external service fails to deliver, the retry logic is visible, and admins can manually retry failed calls.

## Settings and Account Management
The Settings page is reached via the sidebar. There, each user can update their personal profile details such as name, email, and profile picture. A separate section allows password changes with fields for current password, new password, and password confirmation, validated on the client before sending to Supabase. If the application supports notification preferences, toggles let users enable or disable email or SMS reminders. After saving settings, a toast confirms success. A breadcrumb or the sidebar link returns the user to the main dashboard.

## Error States and Alternate Paths
Whenever a user enters invalid form data—such as a missing service selection or incorrectly formatted email—the form displays inline error messages next to the relevant fields, preventing submission. If network connectivity is lost during a critical operation, a full-screen overlay appears with a message about the lost connection and a retry button. Supabase authentication errors, like wrong password or expired session, prompt an inline alert on the login page. For restricted actions, such as a receptionist attempting to delete a service, the application hides those controls based on the user’s role. If a server error occurs during a data mutation, a toast notification displays an error message, and the user can retry the action without losing their progress.

## Conclusion and Overall App Journey
From the moment a staff member signs up and logs in, they move seamlessly into a unified dashboard that surfaces the Therapist Schedule Board by default. With a clear sidebar and a responsive interface, they can switch to the POS screen to complete customer transactions, return to the scheduler to update bookings in real time, or dive into the Admin CMS to manage business data. Managers can pull up detailed reports or configure webhook integrations for SMS reminders and payment confirmations. Throughout the experience, consistent form validation, real-time updates, and meaningful feedback guide each user, ensuring that daily tasks—from booking appointments to processing payments—flow naturally from one screen to the next.
